 Milestone 1.1 — Research & Technical Understanding

1. Internship Application Workflows & Candidate Bottlenecks
Students applying for technical internships typically follow a repetitive manual workflow:
1. Searching across job portals and reading unstructured job descriptions.
2. Submitting the same generic PDF resume regardless of role requirements.
3. Guessing which skills they lack when applications are rejected.
4. Preparing for interviews without structured feedback tied to their actual projects.

Technical Solution:
A PDF resume contains unstructured text that downstream software cannot reliably compare against job requirements. By extracting raw text from uploaded resumes and mapping it into a validated JSON Candidate Profile (separating technical skills, education, projects, and experience), the system creates a clean, machine-readable foundation that every downstream AI module can reuse.

2. Retrieval-Augmented Generation (RAG) Architecture
Standard Large Language Models (LLMs) rely solely on static training data, which causes them to hallucinate outdated or non-existent internship openings when asked for job recommendations.

How RAG Solves This 
Indexing Phase:
 Verified internship descriptions are split into chunks, converted into vector embeddings, and stored in a local vector database (**ChromaDB**).
Retrieval Phase:
 A candidate's structured skills and target roles are used to run a semantic similarity search, retrieving only the top-$k$ real matching internships.
Generation Phase: 
The LLM receives both the retrieved internship descriptions and the structured `CandidateProfile` as context, ensuring all match scores, skill gaps, and cover letters are grounded in real data.

3. Multi-Agent Design Patterns
Handling job matching, skill gap analysis, resume rewriting, cover letter drafting, and mock interviews inside a single monolithic LLM prompt degrades output quality and makes debugging difficult.

Adopted Pattern — Supervisor / Router Multi-Agent Architecture:
Career Assistant (Supervisor Agent): Acts as the central orchestrator, maintaining conversation state and routing user requests to the appropriate specialist.
Job-Resume Matching Agent: Compares the structured candidate profile against retrieved internship postings and ranks compatibility.
Skill Gap Agent: Identifies missing technical skills and tools required for target roles.
Resume Agent: Tailors resume bullet points and project highlights to align with specific job descriptions.
Cover Letter Agent: Drafts role-specific cover letters grounded in the candidate's real projects and achievements.
Interview Agent: Conducts mock technical and behavioral interviews based on the candidate's listed tech stack and projects.

4. Tech Stack Selection & Justification
Frontend UI — React (Vite) + Tailwind CSS: Provides a clean, component-based Single Page Application (SPA) with fast state transitions, structured profile cards, and responsive skill badges—avoiding full-page script reruns.
Backend API Layer — FastAPI + Uvicorn: High-performance asynchronous Python REST API serving structured JSON endpoints (`/api/profiles`, `/api/upload-resume`) with automatic OpenAPI/Swagger documentation.
Data Validation — Pydantic: Enforces strict schema validation on both API requests and LLM-extracted candidate profiles.
PDF Parsing — PyMuPDF (`fitz`): Reliably extracts clean plain text from multi-column student PDF resumes.
LLM Structured Extraction — Gemini API (`google-genai`): Uses native JSON schema enforcement (`response_schema`) to map raw resume text directly into a validated `CandidateProfile`.
Database — SQLite: Provides lightweight relational storage for student metadata, uploaded file paths, raw resume text, and serialized JSON profiles.
